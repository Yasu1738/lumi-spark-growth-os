# データ移行・バックアップ手順

## 1. 既存台帳からの移行（非破壊）

既存台帳（Google Sheets『note記事運用台帳 Ver.0.1』など）は**変更しません**。本システムは取込用にダウンロードしたコピーを読み取るだけです。

### 手順

1. Google Sheetsで「ファイル → ダウンロード → Microsoft Excel (.xlsx)」を選び、PCに保存します。
   （本システムはGoogleアカウントに接続しません。認証情報も扱いません）
2. バックアップを取ります：`python scripts/lumi.py backup --label 移行前`
3. 試し取込でDBを変更せずに結果を確認します。
   ```bash
   python scripts/lumi.py import 台帳.xlsx --sheet 記事台帳 --dry-run --actor 西冨
   python scripts/lumi.py import 台帳.xlsx --sheet 日次アカウント --dry-run --actor 西冨
   ```
   画面では「取込・バックアップ・履歴 → CSV・Excel取込 → 試し取込」。
4. レポートを確認します。
   - `errors`：取り込めなかった行と理由
   - `skipped`：既存IDなどで上書きしなかった行
   - `warnings`：不正URL、定義外の値（例：テーマ「組織」はORGに推測変換せず原文保全）、計測日時不明の24h/72h値など
   - `source_unchanged: true`：元ファイルが変更されていないこと（SHA-256一致）
5. 問題がなければ `--dry-run` を外して実行します（自動で取込前バックアップを作成）。

### 旧台帳38列の取り扱い

| 旧台帳の列 | 移行先 |
|---|---|
| Article_ID、公開日時、タイトル、URL、主目的、副目的、テーマ、想定読者、感情温度、核となる一文、次の仮説、メモ | `articles` の各列（URLは形式検証のみ、確認状態は「未確認」） |
| 24h PV／スキ／コメント（24h期限を計測日時として） | `article_metrics`（区分24h）。経過時間が許容範囲外なら取り込まず警告 |
| 72h PV／スキ／コメント（72h期限を計測日時として） | `article_metrics`（区分72h）。同上 |
| 上記以外（スキ率、基準PV、判定、4象限、残す要素など） | `legacy_json` に原文のまま保全（記事資産台帳の詳細編集で表示） |

注意：旧台帳には実計測時刻の列がないため、「24h期限」「72h期限」列を計測日時として転記し、計測条件メモにその旨を記録します。

## 2. バックアップ

| 方法 | 内容 |
|---|---|
| 画面 | 取込・バックアップ・履歴 → バックアップと復旧 → 今すぐバックアップ |
| CLI | `python scripts/lumi.py backup --label 名前` |
| 自動 | 取込実行前（pre-import）、復旧実行前（pre-restore） |

- 保存先：`backups/`（環境変数 `LUMI_BACKUP_DIR` で変更可）
- 各バックアップには同名の `.json` マニフェスト（作成日時、SHA-256、テーブル別件数）が付きます。
- 推奨：週1回、および大きな編集・取込の前。バックアップフォルダはクラウドではなくPC内・外付けドライブなど、自分で管理できる場所へコピーしてください。
- 人が読める形で残す場合：`python scripts/lumi.py export exports/全データ_YYYYMMDD.xlsx`

## 3. 復旧

1. 一覧で戻したいバックアップを選びます（`python scripts/lumi.py list-backups`）。
2. 復旧します。
   - 画面：バックアップを選び、確認チェックを入れて「復旧する」
   - CLI：`python scripts/lumi.py restore lumi_YYYYMMDD_HHMMSS_xxxxxx_manual.db --yes`
3. 復旧前には次を自動で行います。
   - バックアップの整合性検査（SQLiteの integrity_check、必要テーブルの有無、マニフェストのSHA-256照合）。問題があれば復旧を中止
   - 現在のDBを `pre-restore` として退避
4. 復旧を取り消したい場合は、退避された `pre-restore` ファイルから同じ手順で復旧します。

## 4. 取込できない・してはいけないもの

- 会員の個人情報（氏名、メール、決済情報など）は取り込まないでください。読者理解の要約にも書かないでください。
- noteの画面から自動でデータを集める処理は実装していません。管理画面の数値は人が確認して入力・取込します。
