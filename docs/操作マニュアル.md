# 操作マニュアル

## 0. 基本

1. `streamlit run app/main.py` で起動し、ブラウザで `http://localhost:8501` を開きます。
2. 左のサイドバーで **担当者名** を入力します。入力しないと保存・登録はできません（すべて操作履歴に残ります）。
3. 「サンプルデータを表示」をオフにすると、実データだけで一覧・集計できます。サンプルは実績ではありません。

## 1. 記事を登録・整備する（記事資産台帳）

- **一覧・一括編集**：テーマ、主目的、タイトル構造（`T01,T05` のようにカンマ区切り）、H／V／C、導線段階、本文確認済みを表の中で直接編集し、「変更を保存」。
- **詳細編集**：URL、公開日時、想定読者、中心主張、関連テーマタグ、仮説などを編集。
  - URLは確認できたものだけ入力します。推測で作らないでください。
  - URLを変更すると、URL確認状態は自動で「未確認」に戻ります。
  - 本文を読んで関連性を判断できる状態になったら「本文内容を人間が確認した」にチェックします。
- **新規登録**：記事IDは英数字・ハイフン（例：`LS-A010`）。サンプルを作る場合は区分を「サンプル」に。

## 2. ハブを整える（ハブ構造）

- ハブ名、ハブ記事、関連テーマ、状態、説明を編集して「ハブ情報を保存」。
- 導線ステップは表で追加・削除・並べ替え（順番列）し、「導線ステップを保存」。割当記事は任意。
- 右側の図は確認用です。実線は承認以降、破線は提案・確認段階（仮案を含む）。
- HUB-ORGのハブ記事は「事業承継は、親子関…」の仮登録です。正式な記事名・URLが分かったら記事資産台帳で更新してください。

## 3. 関連記事を推薦してもらう（関連記事推薦）

1. リンク元の記事を選び、件数（2または3）を選びます。
2. 推薦理由、読者が次に得られる価値、推奨リンク文、推奨挿入場所、URL確認状態、関連性の根拠が表示されます。
3. 採用する候補を選び「提案として登録」。この時点の状態は「提案」です。

推薦はタグとルールによる機械的な候補です。本文を確認していない記事は「ルール推定（本文未確認）」と表示されます。

## 4. リンク提案を確認・承認する（リンク承認・貼り付け文）

| 状態 | 誰が・何をしたか |
|---|---|
| 提案 | 推薦エンジンまたは人が候補を登録した |
| 確認 | 人がリンク元・先の内容を読み、つなぐ意味があると判断した |
| 承認 | 承認者が反映してよいと決めた（承認者名必須） |
| note反映 | 人がnoteの編集画面でリンクを設置した（アプリはnoteを操作しない） |
| 表示確認 | 公開ページでリンクが正しく表示・遷移することを人が確かめた |

- 「本番反映」列が「仮案（本番反映不可）」の提案は承認できません。理由（URL未確認、本文未確認、タイトル未照合など）が表示されるので、記事資産台帳で解消してください。
- 却下はいつでも可能で、却下から提案へ戻せます。
- 「この提案の操作履歴」で、日時・担当者・変更内容・承認者を確認できます。

### note貼り付け用文章

1. 「note貼り付け用文章」タブでリンク元記事と含めるリンクを選びます。
2. 生成された文章の右上のアイコンでコピーします。
3. URLが確認できていないリンクには `［URL未確認：このまま貼り付けないでください］` が入ります。仮案の文章は本番に貼らないでください。
4. 全リンクが承認済みでURL・本文確認がそろうと「本番反映可能」と表示されます。それでもnoteへの反映は人が行います。

### リンク検査

不正URL、作成者IDが異なるnoteのURL、重複リンク、自己リンクを一覧表示します。登録前に個別の組み合わせもチェックできます。

## 5. 実績を記録・分析する（記事分析）

- **実績を登録**：計測日時と出典は必須。未計測の項目は空欄のまま（0と入力しない）。
  - 24h値・72h値は、公開日時（時刻まで）からの経過が 18〜30時間／60〜84時間のときだけ登録できます。
  - それ以外（後日見た累積値、公開時刻が不明）は「累積値」として登録してください。
- **記事別実績**：区分ごとに表示。Proxy指標（IMP→PV、スキ/PV、コメント/PV）と、比較時の警告（区分混在、計測時点違い、出典違い、サンプル混在、スキ＞PVなど）を表示します。
- **構造分析**：構造コード別の中央値と記事数。3本未満のコードは「判断しない」と表示。Ver.6.1の初期仮説H1〜H3のデータ充足状況を表示します（判定は人が行う）。
- **アカウント全体**：28日窓などの全体実績。記事別の実績と混ぜないでください。
- **ランキング**：2026-10-24 11:51時点の上位10記事のスキ（累積）。照合できていない7件は未照合のまま。
- **読者理解**：コメントから得た課題・関心をタグと要約で記録。個人名・@アカウントは記録できません。

## 6. 収益導線

- 7段階（認知→信頼→対話→参加意向→有料参加→継続→実践成果）ごとに、担当記事数と確認済み実績を表示します。
- 記事ごとに「つなぐ段階」と収益導線の内容を設定できます。
- 会員数・参加率・収益は、noteの管理画面などで確認できた数値だけを出典つきで記録します。推定値は登録できません。
- 決済機能・会員個人情報は扱いません（noteのメンバーシップ機能を利用する前提）。

## 7. 取込・バックアップ（詳細は「データ移行・バックアップ手順」）

- 取込は必ず「試し取込」で結果を確認してから「取込を実行」。実行時は自動で取込前バックアップを作ります。
- 「今すぐバックアップ」で手動バックアップ。復旧時は、復旧前の状態を自動で退避します。
- 「書き出し」で全テーブルを新しいExcelに出力できます（既存の台帳は上書きしません）。
